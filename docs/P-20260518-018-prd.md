# P-20260518-018 PRD: 任务结果缓存层（Direction S）

## 1. 目标

hermes-agent-collab 在 Redis 中实现任务结果的 TTL 缓存层，使得已完成任务的结果可以被快速查询，避免重复计算。同时提供缓存淘汰策略（LRU/TTL/LFU）和缓存预热接口。

## 2. 背景

当前任务结果（Task.result）在任务完成后直接存储在 TaskManager 内存或 PostgreSQL 中。对于高频查询同一任务结果的场景（如 Web Dashboard 轮询、Agent 热补丁），每次都从数据库读取增加延迟和 DB 负载。

## 3. 设计方案

### 3.1 缓存键结构

```
collab:task_result:<task_id>       → JSON 序列化后的 Task.result
collab:task_result_meta:<task_id> → {"cached_at": timestamp, "access_count": N, "ttl": T}
```

### 3.2 缓存操作

```python
# collaboration/task_cache.py

class TaskResultCache:
    """
    Redis-backed TTL cache for task results.
    Supports get/set/delete and cache metadata tracking.
    """

    def __init__(
        self,
        redis_client,
        default_ttl: int = 3600,      # 1 hour default
        max_cache_size: int = 10000,  # max cached results
    ):
        self._redis = redis_client
        self._default_ttl = default_ttl
        self._max_cache_size = max_cache_size

    async def get(self, task_id: str) -> dict | None:
        """Get cached task result + metadata. Returns None on miss."""
        ...

    async def set(
        self,
        task_id: str,
        result: dict,
        ttl: int | None = None,
    ) -> None:
        """Cache a task result with optional custom TTL."""
        ...

    async def delete(self, task_id: str) -> None:
        """Evict a task result from cache."""
        ...

    async def get_or_compute(
        self,
        task_id: str,
        compute_fn: Callable[[], Awaitable[dict]],  # fetch from DB
        ttl: int | None = None,
    ) -> dict:
        """Cache-aside pattern: try cache first, fall back to compute_fn."""
        ...

    async def invalidate_workspace(self, workspace_id: str) -> int:
        """Evict all cached results for a workspace. Returns count evicted."""
        ...
```

### 3.3 缓存策略

| 策略 | 说明 |
|------|------|
| `ttl` | 固定 TTL，过期自动淘汰（默认 1 小时） |
| `lru` | 最近最少使用，超容量时淘汰 |
| `lfu` | 最不经常使用，结合访问计数淘汰 |

配置项：

```
TASK_CACHE_ENABLED=true
TASK_CACHE_TTL=3600
TASK_CACHE_MAX_SIZE=10000
TASK_CACHE_STRATEGY=ttl  # ttl | lru | lfu
```

### 3.4 缓存预热

```python
async def warm_cache(
    workspace_id: str,
    task_ids: list[str],
    compute_fn: Callable[[str], Awaitable[dict]],
) -> int:
    """Pre-populate cache for a list of task_ids. Returns count warmed."""
```

### 3.5 与 TaskManager 集成

TaskManager 完成任务时自动写入缓存：

```python
class TaskManager:
    def complete_task(self, task_id: str, result: dict):
        self._tasks[task_id].result = result
        self._tasks[task_id].status = TaskStatus.COMPLETED
        # Auto-cache on completion
        if self._task_cache:
            asyncio.create_task(
                self._task_cache.set(task_id, result)
            )
```

## 4. REST API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/collab/tasks/{task_id}/result` | 获取任务结果（缓存优先） |
| POST | `/api/collab/tasks/{task_id}/result/cache` | 手动写入缓存 |
| DELETE | `/api/collab/tasks/{task_id}/result/cache` | 从缓存删除 |
| POST | `/api/collab/workspaces/{id}/cache/warm` | 预热缓存 |

## 5. 环境变量

| 变量 | 说明 |
|------|------|
| `TASK_CACHE_ENABLED` | 启用任务结果缓存（default: true） |
| `TASK_CACHE_TTL` | TTL 秒数（default: 3600） |
| `TASK_CACHE_MAX_SIZE` | 最大缓存条目数（default: 10000） |
| `TASK_CACHE_STRATEGY` | 淘汰策略（default: ttl） |
| `TASK_CACHE_REDIS_KEY_PREFIX` | Redis 键前缀（default: collab:task_result） |
