# PRD: Direction M — API Rate Limiting + 流量控制

## 1. Problem Statement

当前 API 无流量控制，存在以下风险：
- **DoS 风险**：客户端恶意高频请求影响服务质量
- **成本不可控**：LLM 调用按 token 计费，无请求频率限制
- **级联失败**：慢下游导致上游资源耗尽
- **多租户不公平**：无 per-client/per-key 配额隔离

## 2. Architecture

### 2.1 Rate Limiting Strategy

采用 **Token Bucket + Sliding Window** 混合策略：
- **Token Bucket**：控制突发流量（burst），每个 API Key 有独立的 bucket
- **Sliding Window**：精确统计时间窗口内的请求数

### 2.2 分层限制

| 层级 | 限制对象 | 默认值 | 窗口 |
|------|---------|--------|------|
| Global | 全局所有请求 | 1000 req/min | 滑动窗口 |
| Per-API-Key | 每个 API Key | 100 req/min | 滑动窗口 |
| Per-Endpoint | 每个端点 | 200 req/min | 滑动窗口 |
| Burst | 突发容量 | 50 req | Token Bucket |

### 2.3 核心组件

```
RateLimiter (单例)
    ├── TokenBucketRegistry (per-api-key bucket)
    ├── SlidingWindowCounter (per-endpoint + global)
    └── QuotaExceeded → HTTP 429 Too Many Requests
```

### 2.4 Redis-backed Rate Limiting

对于多实例部署，使用 Redis 实现分布式计数：
- `ratelimit:global:{window}` — 全局限流
- `ratelimit:key:{api_key}:{window}` — per-key 限流
- `ratelimit:endpoint:{endpoint}:{window}` — per-endpoint 限流

退化为内存限流（单实例，无 Redis）。

## 3. 接口设计

### 3.1 RateLimitConfig

```python
@dataclass
class RateLimitConfig:
    enabled: bool = True
    storage: str = "memory"  # "memory" | "redis"
    global_limit: int = 1000  # req/min
    per_key_limit: int = 100  # req/min
    per_endpoint_limit: int = 200  # req/min
    burst_capacity: int = 50
    window_size_seconds: int = 60
```

### 3.2 HTTP 响应头

```
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1716000000
Retry-After: 30  (仅 429 响应)
```

### 3.3 429 Too Many Requests

```json
{
  "error": "rate_limit_exceeded",
  "message": "API rate limit exceeded. Retry after 30 seconds.",
  "limit": 100,
  "retry_after": 30,
  "upgrade": "Contact support for higher limits"
}
```

## 4. 实现计划

### 4.1 Phase 1: 内存版 RateLimiter
- `collaboration/rate_limiter.py` — TokenBucket + SlidingWindowCounter
- FastAPI 中间件 `RateLimitMiddleware`
- 拦截所有 `/api/` 端点

### 4.2 Phase 2: Redis-backed 分布式限流
- Redis INCR + EXPIRE 实现滑动窗口
- `get_config()` 读取 `RATE_LIMIT_STORAGE=redis|memory`

### 4.3 Phase 3: per-key 配额管理
- API Key 级别配额配置
- `X-API-Key` 头解析 + 限流

## 5. 向后兼容

- `RATE_LIMIT_ENABLED=false` 完全禁用限流（退化为当前行为）
- 现有 API 端点无需修改
- 429 响应符合 RFC 6585
