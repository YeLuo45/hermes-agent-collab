---

## 1. Overview / 背景

hermes-agent-collab 当前已有基础 EventBus（`events.py`），但仅支持进程内发布-订阅。参考 nanobot 的 Async MessageBus 架构，需将其升级为真正的分布式消息总线，支持多 Channel 适配器接入。

---

## 2. Goals / 目标

- 将现有 EventBus 改造为 nanobot-style AsyncMessageBus，支持跨进程/跨服务通信
- 引入 Channel Adapter 模式，统一封装 HTTP/WebSocket/SSE 三种传输通道
- 消息路由与 channel 解耦，添加消息队列缓冲和 dead-letter 处理
- 保持向后兼容，不破坏现有 API

---

## 3. Core Features / 核心功能

### 3.1 AsyncMessageBus 重构

```
MessageBus (核心)
    ├── Publisher: emit(event) → 消息路由
    ├── Subscriber Registry: 维护 (event_type, workspace_id, callback)
    ├── Router: 根据 event_type + workspace_id 路由到对应 channel
    └── Channel Registry: 管理多个 Channel Adapter
```

核心变更：
- `EventBus` → `AsyncMessageBus`，支持 asyncio 原生并发
- 添加 `ChannelAdapter` 抽象基类
- 添加 in-memory message queue（asyncio.Queue）
- 添加 dead-letter queue（失败消息暂存）

### 3.2 Channel Adapter 模式

```python
class ChannelAdapter(ABC):
    @abstractmethod
    async def publish(self, event: Event) -> bool: ...

    @abstractmethod
    async def subscribe(self, handler: Callable) -> None: ...

    @abstractmethod
    async def start(self) -> None: ...

    @abstractmethod
    async def stop(self) -> None: ...
```

实现三个适配器：
1. **WebSocketChannelAdapter** — 封装现有 WebSocket 广播逻辑
2. **SSEChannelAdapter** — 封装现有 SSE (`/api/collab/sse/{workspace_id}`)
3. **HTTPWebhookAdapter** — 支持向外部 HTTP 端点推送事件（nanobot-style）

### 3.3 消息重试与 Dead-Letter

```python
@dataclass
class DeadLetterEvent:
    event: Event
    error: str
    attempts: int
    first_failure: datetime
    last_failure: datetime
```

- 消息发送失败自动重试（指数退避，最多 3 次）
- 重试耗尽后写入 dead-letter store（JSON 文件）
- 提供 `/api/collab/dead-letters` GET endpoint 读取

### 3.4 Backpressure 机制

- 每个 workspace 独立 queue，大小上限 1000
- 超出上限时丢弃最旧消息并记录 metric
- 提供 `/api/collab/metrics` 暴露 queue 长度、drop 计数

---

## 4. Non-Goals / 非目标

- 不实现持久化消息队列（RabbitMQ/Kafka）
- 不改变现有 REST API 端点
- 不重构 storage 层

## 8. Technical Approach / 技术方案

- Python asyncio + 标准库 Queue
- 重试：指数退避 `2^attempts * 0.1s`，最大 3 次
- Dead-letter 文件锁保护并发写入
- 向后兼容：通过 `_manager_cache` 保持现有 API 不变
