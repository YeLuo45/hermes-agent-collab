# PRD: Direction L — Redis Channel Adapter

## 1. Problem Statement

当前 SSE (Server-Sent Events) 作为实时事件推送机制存在以下局限：
- **无消息持久化**：客户端断线重连后无法获取断线期间的事件
- **水平扩展困难**：多实例部署时无法跨实例推送事件
- **背压处理缺失**：快速生产者可能导致慢消费者事件积压
- **无消息过滤**：客户端收到所有事件后自行过滤

Redis Pub/Sub + Streams 提供成熟的事件分发方案，可解决以上问题。

## 2. Architecture

### 2.1 Redis Stream vs Pub/Sub

| 特性 | Redis Pub/Sub | Redis Streams |
|------|-------------|---------------|
| 消息持久化 | ❌ | ✅ (Capped Stream) |
| 断线重连 | ❌ (丢失) | ✅ (读取历史) |
| 消费者组 | ❌ | ✅ (XREADGROUP) |
| 消息确认 | ❌ | ✅ (XACK) |
| 适用场景 | 实时广播 | 任务队列 / 事件溯源 |

**决策**：混合模式
- `collab.events` — Stream，保留最近 10000 条事件，支持断线重连
- `collab:{session_id}:events` — Pub/Sub channel，用于单会话实时推送

### 2.2 Channel Adapter 架构

```
HookEvent 触发
    ↓
ChannelPublisher (广播到所有 Adapter)
    ↓
    ├── RedisStreamAdapter → XADD collab.events
    ├── RedisPubSubAdapter → PUBLISH collab:{session_id}:events
    └── (保留) SSEAdapter → HTTP SSE (向后兼容)
```

### 2.3 事件消费模型

```python
# Consumer 注册
class EventConsumer:
    session_id: str
    last_event_id: str  # 断线重连时从 Stream 恢复

# XREADGROUP 消费流程
STREAM READER GROUP → 消费者组支持多实例水平扩展
XACK → 消息确认后删除
XPENDING → 检查未确认消息实现重投
```
