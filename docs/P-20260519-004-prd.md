# Direction AO: API 限流与配额管理（端到端）

## 1. 目标

为 hermes-agent-collab 提供完整的 API 限流与配额管理端到端解决方案，基于 CacheLayer（Direction AM）实现 Sliding Window 限流，覆盖 Agent、Workspace、API Key 多个维度的请求配额控制。

## 2. 背景

当前系统（Direction AN）有 Dashboard Admin UI，但没有完整的限流和配额管理能力。协作场景中需要：
- 防止 API 滥用，保护后端服务稳定性
- 按 Workspace / API Key / Agent 多维度配额控制
- 用户可配置的限流策略（软限制 + 硬限制）
- 配额耗尽时的友好错误提示（Retry-After 头）
- 管理员可实时查看配额使用情况

## 3. 设计方案

### 3.1 核心模块

**RateLimitPolicy** — 限流策略数据模型：
- `policy_id`, `name`, `description`
- `dimensions`: "workspace" | "api_key" | "agent" | "global"
- `limit_type`: "sliding_window" | "fixed_window" | "token_bucket"
- `requests_per_window`: int
- `window_seconds`: int
- `burst_limit`: int（可选，突发容量）
- ` scopes`: list[str] — 作用域（如 ["POST /tasks", "GET /agents"] 或 ["*"]）
- `enabled`: bool
- `created_at`, `updated_at`

**QuotaUsage** — 配额使用记录：
- `workspace_id` / `api_key_id` / `agent_id`（至少一个）
- `policy_id`
- `used_count`: int
- `window_start`: datetime
- `last_request_at`: datetime

**RateLimitDecision** — 限流决策结果：
- `allowed`: bool
- `limit`: int
- `remaining`: int
- `reset_at`: datetime
- `retry_after_seconds`: int（仅当 denied 时）

### 3.2 RateLimitManager

限流管理器，负责：
- 加载所有启用策略到内存缓存（TTL 60s）
- 对每个请求执行限流检查（check_limit）
- 消耗配额（consume）
- 策略 CRUD + 分配到 Workspace/API Key

**算法 — Sliding Window Counter**：
1. 从 Redis Sorted Set 获取当前窗口的请求时间戳
2. 清理过期条目（早于 window_start）
3. 计算当前请求数是否 < limit
4. 若允许，添加当前时间戳到 Sorted Set
5. 设置 Sorted Set TTL 为 window_seconds

**多策略匹配**：请求同时匹配多条策略时，取最严格的（剩余最少）。

### 3.3 Middleware 集成

在 `server.py` 中注册限流中间件：
- 读取请求的 `X-API-Key` 头和 `X-Workspace-ID` 头
- 提取 `method + path` 作为 scope
- 调用 `RateLimitManager.check_and_consume()`
- 若 denied，返回 429 + Retry-After 头

### 3.4 REST API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/ratelimit/policies` | 列出所有策略 |
| POST | `/ratelimit/policies` | 创建策略 |
| GET | `/ratelimit/policies/{id}` | 获取策略详情 |
| PUT | `/ratelimit/policies/{id}` | 更新策略 |
| DELETE | `/ratelimit/policies/{id}` | 删除策略 |
| POST | `/ratelimit/policies/{id}/assign` | 分配策略到目标 |
| GET | `/ratelimit/usage/{target_type}/{target_id}` | 查询配额使用 |
| GET | `/ratelimit/check` | 手动触发限流检查 |
| GET | `/ratelimit/stats` | 全局限流统计 |

### 3.5 配额分配

- Workspace 级别：通过 `POST /ratelimit/policies/{id}/assign` + `target_type=workspace`
- API Key 级别：创建时自动附加默认策略
- 全局限量：`target_type=global`
