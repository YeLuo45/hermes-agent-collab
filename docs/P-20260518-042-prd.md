# Direction X: 任务依赖图可视化 API

## 1. 目标

为 hermes-agent-collab 提供任务依赖图（Task DAG）可视化 REST API，允许客户端获取任务的依赖关系、结构化的执行计划图，用于前端可视化、调试和执行流程分析。

## 2. 背景

当前系统（Direction S/T）支持任务创建、执行管理、结果缓存和 Webhook 通知，但缺少任务依赖关系的可视化接口。协作场景中，用户需要了解：
- 哪些任务在等待当前任务完成
- 任务图的拓扑排序
- 并行执行机会（独立分支）
- 执行瓶颈识别（关键路径）

## 3. 功能范围

### 3.1 核心功能

#### 3.1.1 任务依赖图数据模型

```python
class TaskGraphNode(BaseModel):
    task_id: str
    title: str
    status: TaskStatus
    assigned_agent: str | None
    created_at: datetime
    started_at: datetime | None
    completed_at: datetime | None
    depends_on: list[str]  # 依赖的任务 ID 列表
    dependents: list[str]  # 依赖当前任务的任务 ID 列表（反向索引）

class TaskGraphEdge(BaseModel):
    from_task: str
    to_task: str
    edge_type: Literal["dependency", "blocks"]

class TaskGraphResponse(BaseModel):
    workspace_id: str
    nodes: list[TaskGraphNode]
    edges: list[TaskGraphEdge]
    stats: TaskGraphStats

class TaskGraphStats(BaseModel):
    total_tasks: int
    pending_tasks: int
    running_tasks: int
    completed_tasks: int
    failed_tasks: int
    parallel_opportunities: int  # 可并行执行的最大分支数
    critical_path_length: int    # 关键路径长度（最长依赖链）
```

#### 3.1.2 DAG 拓扑分析

- **拓扑排序**：返回任务执行顺序（Kahn 算法）
- **关键路径**：计算最长依赖链（用于性能估算）
- **并行机会检测**：识别可同时执行的最大任务集
- **循环检测**：检测并报告依赖环

```python
class TopologicalSortResponse(BaseModel):
    sorted_task_ids: list[str]
    has_cycles: bool
    cycle_tasks: list[list[str]]  # 环形依赖的任务组
    levels: list[list[str]]  # 按层级分组，同层可并行
```

#### 3.1.3 执行计划生成

```python
class ExecutionPlan(BaseModel):
    phases: list[ExecutionPhase]
    estimated_duration_median: float  # 估算中位耗时（秒）

class ExecutionPhase(BaseModel):
    phase_id: int
    tasks: list[str]
    can_run_parallel: bool
    depends_on_phases: list[int]
```

### 3.2 API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/workspaces/{id}/graph` | 获取工作空间完整任务依赖图 |
| GET | `/workspaces/{id}/graph/toposort` | 获取拓扑排序结果 |
| GET | `/workspaces/{id}/graph/plan` | 获取分阶段执行计划 |
| GET | `/tasks/{id}/downstream` | 获取任务下游依赖（谁依赖此任务） |
| GET | `/tasks/{id}/upstream` | 获取任务上游依赖（此任务依赖谁） |

### 3.3 配置

无新增环境变量（使用现有 WORKSPACE_* 配置）。

- `collaboration/models.py`：新增 TaskGraphNode/Edge/Stats、TopologicalSortResponse、ExecutionPlan/Phase 模型

### 4.3 关键算法

**拓扑排序（Kahn 算法）**：
1. 计算所有节点的入度
2. 将入度为 0 的节点入队
3. 弹出节点，将其加入排序结果，减少其下游节点入度
4. 重复直到队列为空或检测到环

**关键路径**：
1. 对 DAG 进行拓扑排序
2. 计算每个节点的最早完成时间（EFT = EST + duration）
3. 反向遍历计算最晚开始时间（LST）
4. 关键路径 = EFT == LST 的节点链

**分阶段执行计划**：
1. 拓扑排序后，按层级分组（level = max upstream levels + 1）
2. 每层的任务可以并行执行
3. 相邻层级之间有依赖关系
