# P-20260518-003 PRD: thunderbolt-inspired SQLite Offline-First Storage

## 1. Overview

**Project**: hermes-agent-collab  
**Proposal ID**: P-20260518-003  
**Direction**: B  
**Inspiration**: thunderbolt — offline-first local-first data, SQLite WAL mode, zero network dependency  
**Stage**: prd_pending_confirmation

## 2. Problem Statement

Current storage uses JSON files with fcntl file locking. Limitations:
- No offline resilience: data inaccessible if file is locked
- Poor concurrency: fcntl locks are advisory, JSON rewrite is all-or-nothing
- No crash recovery: corrupt JSON loses all data
- No query capability: must load entire file to search

## 3. Proposed Solution

Add SQLite as an alternative storage backend with WAL (Write-Ahead Logging) mode, providing:
- **Offline-first**: All data local, no network dependency
- **Crash recovery**: WAL journal ensures atomic commits
- **Better concurrency**: Concurrent reads + single writer via SQLite's MVCC
- **Query capability**: SQL queries across entities

## 4. Design

### 4.1 Dual-Backend Storage Architecture

```
JsonFileStore          SQLiteStore
    │                      │
    └────────┬─────────────┘
             ▼
    StorageBackend (abstract)
    ├── list()
    ├── get(key)
    ├── upsert(entity)
    └── delete(key)
```

Config in `workspace.json` or `config.json`:
```json
{
  "storage_backend": "sqlite",  // or "json"
  "sqlite_path": ".hermes/hermes-agent-collab.db"
}
```

### 4.3 WAL Mode Configuration

```python
import sqlite3

def open_db(path: Path) -> sqlite3.Connection:
    conn = sqlite3.connect(path, check_same_thread=False)
    conn.execute("PRAGMA journal_mode=WAL")
    conn.execute("PRAGMA synchronous=NORMAL")
    conn.execute("PRAGMA busy_timeout=5000")
    conn.execute("PRAGMA foreign_keys=ON")
    return conn
```

## 6. Acceptance Criteria

1. `StorageBackend.for_tasks(ws_path)` returns correct backend based on config
2. `SQLiteStore` passes same CRUD tests as `JsonFileStore`
3. WAL mode enabled: `PRAGMA journal_mode` returns `wal`
4. Events append correctly: `INSERT` then `SELECT` returns new events
5. Concurrent access: two processes can read simultaneously while one writes
6. Crash recovery: data survives `kill -9` during write
7. Import works: `import collaboration.storage` succeeds with no new deps
8. Backward compatible: existing JSON workspace still works if `storage_backend: json`
