# Direction AA: 多租户隔离

## 1. 目标

为 hermes-agent-collab 提供 workspace 级别的资源隔离和配额管理能力，确保不同租户的数据、计算资源、API 配额完全隔离，防止单租户耗尽全局资源。

## 2. 背景

当前系统（Direction Z）支持敏感数据脱敏，但所有 workspace 共享同一个 Redis/PgSQL 实例和系统级配额。协作场景中，平台需要：
- Workspace 之间数据严格隔离（不能跨租户访问）
- 每个租户有独立的 API 速率配额
- 资源使用量可量化（任务数、Agent 数、存储量）
- 配额超限时的降级策略

## 3. 功能范围

### 3.1 核心功能

#### 3.1.1 Workspace 隔离层

```python
class TenantContext:
    """线程局部的租户上下文"""
    workspace_id: str
    user_id: str | None
    is_admin: bool

class TenantIsolationMiddleware:
    """自动注入 TenantContext 并校验跨租户访问"""
```

#### 3.1.2 资源配额管理器

```python
class QuotaManager:
    """每个 workspace 的资源配额控制"""
    
    def check_quota(self, workspace_id: str, resource: str, cost: int = 1) -> bool:
        """检查配额是否允许"""
    
    def record_usage(self, workspace_id: str, resource: str, cost: int = 1) -> None:
        """记录资源使用"""
    
    def get_usage(self, workspace_id: str) -> dict[str, Any]:
        """获取当前使用量"""
    
    def reset_quota(self, workspace_id: str) -> None:
        """重置配额（周期性）"""
```

#### 3.1.3 配额配置

```python
# Workspace 配额配置（workspace.config.quota）
QUOTA_TASKS_MAX = 1000          # 最大任务数
QUOTA_AGENTS_MAX = 50           # 最大 Agent 数
QUOTA_TASKS_PER_HOUR = 100     # 每小时任务创建限额
QUOTA_API_CALLS_PER_MIN = 60   # 每分钟 API 调用限额
QUOTA_STORAGE_MB = 500          # 存储限额（MB）
QUOTA_WEBHOOKS_MAX = 20        # 最大 Webhook 数
```

#### 3.1.4 隔离存储适配器

```python
class TenantAwareStorage:
    """为每个 workspace 自动加上 tenant prefix"""
    
    def _tenant_key(self, key: str, workspace_id: str) -> str:
        return f"tenant:{workspace_id}:{key}"
```

#### 3.1.5 跨租户操作防护

- 所有 API 端点自动校验 workspace_id 匹配
- 跨 workspace 的 task/agent 查询返回 403
- Admin API 需额外 `X-Tenant-Admin: true` 头部

### 3.2 API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/tenants` | 列出所有租户及配额使用情况 |
| GET | `/admin/tenants/{id}/quota` | 获取指定租户配额 |
| PUT | `/admin/tenants/{id}/quota` | 更新租户配额 |
| POST | `/admin/tenants/{id}/quota/reset` | 重置租户配额 |
| GET | `/workspaces/{id}/usage` | 获取当前 workspace 资源使用量 |

### 4.3 配额算法

**滑动窗口计数器**（每分钟/每小时）：
- 使用 Redis ZSET 实现滑动窗口：`tenant:{wid}:rate:{resource}`
- ZSET score = timestamp，value = unique request id
- 窗口内 count = ZCARD
- 过期数据自动清理（ZREMRANGEBYSCORE）

**固定窗口**（月度/永久配额）：
- 计数器存储在 Redis：`tenant:{wid}:quota:{resource}`
- INCR 原子递增，EXPIRE 设置过期时间
