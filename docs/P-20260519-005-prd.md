# Direction AS: 深度链路追踪（OpenTelemetry Span 关联）

## 1. 目标

为 hermes-agent-collab 提供完整的分布式链路追踪能力，基于 Direction AG 已有的 TracingManager，扩展为端到端 Span 关联覆盖，将 HTTP 请求、WebSocket 消息、Task 执行、Agent 协作全链路串联，实现请求级别的完整调用链追踪。

## 2. 背景

当前系统（Direction AO）有完整的限流机制，但缺乏细粒度的请求级别链路追踪。协作场景中需要：
- 每个 HTTP 请求有唯一 Trace ID，可追溯全链路
- Task/Agent 执行 Span 关联到父 Trace
- WebSocket 消息的请求-响应关联
- 慢查询识别（自动标记超阈值 Span）
- Span 事件（annotation）记录关键节点

## 3. 设计方案

### 3.1 核心增强

**SpanContext 传播**：
- 每个请求自动创建 root Span
- SpanContext 通过 ContextVar 在协程间传播
- Task/Agent 执行自动继承父 Trace ID

**关键改进**：
- `distributed_tracing.py` 已有 TracingManager + Jaeger — 扩展为完整 OTel SDK
- Span 级别：DEBUG/INFO/WARN/ERROR
- 超时追踪：自动标记执行时间超过阈值的 Span
- 事件注解：记录关键节点的键值对

**Span 结构**：
```
Span {
    trace_id, span_id, parent_span_id
    name, service.name
    start_time, end_time, duration_ms
    attributes: {http.method, http.url, http.status_code, user.id, workspace.id}
    events: [{name, timestamp, attributes}]
    status: {code, message}
}
```

**Collector 输出**：
- OTLP HTTP Exporter（默认，推送到 Jaeger/OTEL Collector）
- 可配置 batch size 和导出间隔

### 3.2 WebSocket Trace 关联

- 每个 WebSocket 连接携带 `X-Trace-ID` 头
- 连接握手时创建 WebSocket Span
- 每条消息处理创建 child Span
- 消息-响应通过 `span_id` 关联

### 3.3 Task/Agent 执行追踪

- Task 创建时记录 task Span
- Agent 执行记录 agent Span
- Orchestration 阶段变化记录 phase event
- 失败时记录 error event + status

### 3.4 REST API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/traces/list` | 列出最近的 Trace |
| GET | `/traces/{trace_id}` | 获取完整 Trace（含所有 Span） |
| GET | `/traces/stats` | 追踪统计（QPS、p50/p95/p99 延迟） |
| POST | `/traces/annotate/{span_id}` | 手动添加 Span 注解 |
| GET | `/traces/slow` | 慢查询 Span（>阈值） |
