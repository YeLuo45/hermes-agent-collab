# PRD: Direction P — 分布式 Tracing（OpenTelemetry）

## 1. Problem Statement

当前系统缺乏请求链路追踪能力：
- **无调用链视图**：无法看到一次请求经过的所有服务和组件
- **性能瓶颈定位困难**：慢请求无法确定卡在哪一个环节
- **跨服务传播缺失**：一个请求在多个组件间流转时，trace_id 未传递
- **调试依赖日志**：只能通过分散的日志推断执行路径

OpenTelemetry 提供统一的可观测性解决方案，支持 traces、metrics、logs 三大信号。

## 2. Architecture

### 2.1 OpenTelemetry 核心概念

```
Trace: 请求的完整调用链
├── Span: 一次操作（HTTP 调用、数据库查询、LLM 调用）
│   ├── span_id: 唯一标识
│   ├── trace_id: 所属 Trace
│   ├── parent_span_id: 父 Span（形成树形结构）
│   ├── start_time / end_time
│   └── attributes（键值对）
```

### 2.2 组件架构

```
collab_api.py (FastAPI)
    ↓ (OTLP gRPC)
TracingMiddleware
    ↓
collab components (TaskManager, AgentRegistry, etc.)
    ↓ (context propagation)
External services (LLM APIs, databases)
```

### 2.3 Span 层级设计

| Span Name | 类型 | 属性 |
|-----------|------|------|
| `http.request` | Server | method, route, status_code |
| `task.execute` | Internal | task_id, priority, complexity |
| `agent.llm.call` | Client | model, prompt_tokens, completion_tokens |
| `db.query` | Client | statement, rows_affected |
| `channel.publish` | Internal | adapter, event_type |
| `orchestration.execute` | Internal | orchestration_id, phase |

## 3. 接口设计

### 3.1 TracingConfig

```python
@dataclass
class TracingConfig:
    enabled: bool = True
    service_name: str = "hermes-agent-collab"
    exporter: str = "otlp"  # "otlp" | "console" | "jaeger"
    otlp_endpoint: str = "http://localhost:4317"  # gRPC endpoint
    sample_rate: float = 1.0  # 1.0 = 100%, 0.1 = 10%
    propagator: str = "tracecontext"  # "tracecontext" | "b3" | "baggage"
```

### 3.2 REST API 端点

```
GET /api/v1/traces
    Query: ?trace_id=xxx&service_name=xxx&limit=100
    Response: { traces: [...] }

GET /api/v1/traces/{trace_id}
    Response: { trace_id, spans: [...] }
```

## 4. 实现计划

### 4.1 Phase 1: 基础 Tracing
- `collaboration/tracing.py` — OpenTelemetry SDK 初始化
- `TracingMiddleware` — FastAPI 请求追踪
- auto-instrumentation for FastAPI

### 4.2 Phase 2: 手动埋点
- TaskManager span
- AgentRegistry span
- LLM 调用 span（带 token 统计）
- 数据库查询 span

### 4.3 Phase 3: Context 传播
- W3C Trace Context 头部传播
- Redis Stream/PubSub 携带 trace_id
- 外部 HTTP 调用自动注入 trace context
