# P-20260518-008 PRD: API Key Auth + Real-time Web Dashboard (Direction G)

## 1. Overview

**Project**: hermes-agent-collab  
**Proposal ID**: P-20260518-008  
**Direction**: G  
**Inspiration**: chatdev-design (monitoring), thunderbolt-design (state persistence), generic-agent-design (auth)

Two focused additions: (1) API Key authentication protecting all REST endpoints, and (2) a real-time Web Dashboard using the existing SSE streams for live visualization.

## 2. Architecture

### 2.1 API Key Authentication

- **API Key model**: `key_id` (hash), `key_secret` (hash of actual key), `name`, `workspace_id`, `scopes`, `created_at`, `last_used_at`, `is_active`
- **Storage**: `api_keys.json` via JsonFileStore
- **Header**: `X-API-Key: <key>` on all protected endpoints
- **Scopes**: `read`, `write`, `admin` (workspace-scoped)
- **No external dependencies** — use `hashlib.pbkdf2_hmac` for key hashing

### 2.2 Web Dashboard

Single HTML file (`dashboard/index.html`) that:
- Connects to SSE streams at `/api/collab/v1/events`
- Shows live workspace overview (agents, tasks, skills counts)
- Displays real-time event feed with filtering
- Shows active orchestrations with phase indicators
- Connects to WebSocket at `/api/collab/v1/ws` for bidirectional updates

### 2.3 Dashboard UI Layout


## 3. API Key Auth Design

### 3.1 Endpoints

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | /auth/keys | admin | Create API key |
| GET | /auth/keys | read | List keys (masked) |
| DELETE | /auth/keys/{key_id} | admin | Revoke key |
| POST | /auth/verify | none | Verify key validity |
| GET | /auth/keys/{key_id} | read | Get key metadata |

### 3.2 Request/Response Models

```python
class ApiKeyCreate(BaseModel):
    name: str
    workspace_id: str
    scopes: list[str]  # ["read", "write", "admin"]

class ApiKeyResponse(BaseModel):
    key_id: str
    name: str
    workspace_id: str
    scopes: list[str]
    created_at: str
    last_used_at: Optional[str]
    is_active: bool
    # Only returned on creation:
    key_secret: Optional[str]  # only on create, never again

class ApiKeyListResponse(BaseModel):
    keys: list[ApiKeyResponse]
```

### 3.3 Security

- API key secret shown only once at creation (never stored in plain text)
- Keys hashed with PBKDF2-HMAC-SHA256 (100,000 iterations, random salt)
- Workspace isolation: keys scoped to single workspace
- Failed auth: HTTP 401 with generic "Invalid API key" (no user existence leak)
- Rate limit header: `X-RateLimit-Remaining` on all responses

### 5.2 Auth Middleware Flow

```
Request → X-API-Key header
  → Extract key → Hash → Lookup in api_keys.json
  → Verify workspace match + scope coverage
  → Attach `workspace_id` + `scopes` to request.state
  → Proceed or 401
```

### 5.3 Dashboard Route

`GET /dashboard` → returns `dashboard/index.html` (served from Python, no separate static server needed)

## 6. Constraints

- **No new Python dependencies** — use stdlib `hashlib` for hashing
- Dashboard is pure client-side HTML (no npm/build)
- Auth is opt-in per workspace (existing workspaces continue working without keys)
- API keys are workspace-scoped (no cross-workspace access)

## 7. Acceptance Criteria

1. All `/auth/*` endpoints return correct HTTP status codes
2. API key secret shown only at creation
3. Unauthenticated requests to protected endpoints return 401
4. Dashboard loads at `/dashboard` and connects to SSE
5. Dashboard shows live agent/task/orchestration counts
6. Event feed filters work correctly
7. Backward compatible: no auth required unless `X-API-Key` header present
8. Dashboard works without API key in read-only mode
